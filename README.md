## Atlas 完整界面主题

「关联与 MOC」读取失败时会显示独立的索引恢复面板，可更新当前知识库索引；成功后恢复三种整理模式。索引更新不等于执行笔记整理。

在主题选择器选择 **Atlas**，进入独立的 Atlas 导航和全部业务页面；经典五主题继续可选。“将 Atlas 设为默认主题”决定下次启动/刷新，当前窗口切换不自动改变默认。Atlas 设置中可选择浅色、深色或跟随系统，以及强调色；语言、字体、字号、密度和动效与应用设置共用。

首页四项指标下默认展开“系统架构与运行状况”，节点可跳转；平台接收、查询、保存与回执分别呈现最近读取结果，未知与过期状态不会显示为成功。切换界面不会迁移仓库、恢复积压或调用模型。在线备份、同盘迁移、人工 MOC 与消息绑定沿用现有业务权限和确认流程。

# Fiber bundle

Fiber bundle 是本机知识库应用，提供 macOS 桌面 GUI 和本机 Web 管理页。它可以接入 Markdown / Obsidian 仓库，保存消息和文件原件，审核提取结果，按权限检索笔记，并为外部 Agent 提供只读知识工具。

本 README 面向日常使用。实际发布版本、验证结果和待完成项目见 [项目状态](docs/STATUS.md)；API、配置合同和维护入口见 [技术参考](docs/TECHNICAL_REFERENCE.md)。源码中存在尚未发布的功能，以下会在影响操作的位置说明。

## 首页与资料入口（0.6.0a2）

登录后进入首页。首页只读取已有状态：消息入口、后台、处理队列、当前范围、近期执行和费用；配置存在、历史成功和当前可用分别显示。索引数字来自已保存缓存，不代表扫描过当前磁盘。失败时显示读取时间及保留的数据；最近50/100条不是全系统累计数。

- **资料导入**：先选择处理身份与知识库，再选择普通资料或 fake-expert；高级处理限制在折叠设置中，原件与文件草稿不会跨会话恢复。
- **收件箱**：集中查看审批、批次、文档、媒体、视频和自动处理异常，按来源筛选并点击条目进入原操作；审核、发布、重试和恢复继续要求具体确认。
- **首页关系图**：表示资料和权限的依赖关系，不是实时流量。点击节点打开对应配置；首页刷新不会启动模型、入口、索引或发布。
- 首先读取4项核心状态，其余逐项加载；隐藏窗口暂停首页轮询。消息入口活跃时10秒、空闲60秒；执行/批次活跃30秒、空闲60秒；费用300秒。失败后停止高频刷新，可手动重读。
- **快捷导航**：点击页头搜索按钮或按 ⌘K / Ctrl+K，在本机筛选页面和导入入口；不会搜索资料或启动处理。
- **费用**：首页展示近30天估算及逐日表格，读取有界60天账本供前期比较；数据缺失或费用未知时不比较。完整调用与预算账本在“用量与费用”查看。
- 保留 Cursor、Oracle、Tesla 三主题及已有字体、密度设置。桌面保存窗口位置与大小；原显示器不可用时回到可见区域。

## 项目专业资料 Skill

在 **资料与版本 → 专业资料 Skill** 查看本实例的 `skills/fake-expert/` 路径。放入完整 Skill 目录，包含 `SKILL.md`、`scripts/`、`references/`、`assets/`、`agents/` 和依赖声明；仅复制说明文件不能运行完整编译。选择本机已安装的固定离线编译镜像摘要，点击“检查并保存 Skill 设置”。检查不调用模型，也不自动下载依赖。本轮支持与原生文本 PDF 协议兼容的完整 fake-expert；扫描/加密或不兼容输入显示实际原因，不自动改为 OCR。

更新该目录后，下一份明确选择 fake-expert 的原生文本 PDF 会检查新版并冻结独立快照；旧任务、暂停恢复和同一次提交的重复请求仍使用原快照。关闭设置只影响新任务，不删除历史快照。更新不修改既有笔记、模型、库保存规则或费用账本，也不重放历史资料；出错时显示原因，不静默退回普通提取。Pi 仍须目标库的模型与外发授权，并按统一模型消耗预算执行；完整产物仍为 Draft、语义审核 deferred。目录和旧快照均纳入加密备份，详情见[技术参考](docs/TECHNICAL_REFERENCE.md#project-skills)。

## 统一库与自动处理（0.6.0a1 本机已部署）

首次安装应按实际启动配置访问管理页；默认端口为 8765。不同实例使用独立数据目录、端口与浏览器 profile。升级不会自动开启旧库策略。旧版保存与人工审核方式继续保留。

1. 在 **知识库 → 保存规则** 读取目录，选择统一库预设并预览/确认。默认 MOC 为 `Map`，未分类正文为 `Inbox`，明确分类后为 `Resource`，完整专家包为 `Book/<标题>-Draft`，图片为 `Attachments/images`，非图片原件为 `Attachments/pristin`。可逐项改目录；专家包内部保持完整。
2. 在 **Agent 与客户端** 为处理身份明确授予该库的查询、新增、原件权限。在知识库设置默认查询库；在 **消息入口** 把飞书默认库及自动归档目标设为同一库，并使用该身份。GUI 导入会优先预填有权的默认库，不会因此增加任何权限。
3. 在 **保存规则 → 自动审核与发布** 选择处理身份、允许类型、审核方式与发布方式。默认人工；规则方式只检查来源/结构/覆盖，不验证语义。模型方式引用已有执行配置，须允许发送来源内容并有实际费用额度，缺配置或未知费用不重试。
4. 在 **资料导入** 使用两个独立按钮：**普通资料导入** 和 **fake-expert 专用导入**。普通入口处理原生文本、Markdown、PDF、Office、已支持的 OCR 等；已知微信聊天 ZIP 走普通解析，未知 ZIP 只归档。专用入口固定 PDF 与完整专家 runtime，workpack 单独绑定。未配置 Worker 时只能保存原件，界面不冒充提取成功。
5. 已启用自动策略的新任务由后台完成提取、系统审核、发布和索引；网页关闭不影响后台。历史资料不会自动重放。任务状态和异常原因可在 **自动审核与发布** 中查看；原件副本失败可单独核对恢复，不必重提取或覆盖已编辑附件。
6. 在知识关联提交明确 MOC 后，只有 `moc_archive_mode=automatic` 才自动把普通正文移到 Resource；旧策略只准备预览。多 MOC 目标不一致时待选择，取消关联不移回 Inbox；Book 不随 MOC 搬动。

飞书知识机器人须单独启用专家指令及额度。本人私聊可直接回复一个已接收的 PDF，发送 **用fake-expert处理文件**；也可先发该命令，再在五分钟内上传一个 PDF。多附件时按机器人提示选择，取消用 **取消fake-expert**；群聊、转发正文、伪造回复关系不授权执行。原件未下载会等待；没有完整 runtime 或配套 workpack 时显示实际暂停原因，普通引擎不会替代专家引擎。Draft 保持 `knowledge_verified=false` / 语义审核 deferred。

合并旧库：在目标库 **保存规则 → 合并其他知识库到此库**，选执行身份、源库、历史文件、目标授权清单及待切换入口；只读预检后冻结摘要。先创建完整加密备份，再填备份目录与密码并确认执行。进度逐阶段持久化；源文件保留为副本，Fiber bundle 默认检索只显示当前位置，Obsidian 仍能看到旧目录。完成后相关消息入口和 Agent 保持暂停，需核对新范围后显式启用。未知状态用“核对/继续”，回退只删除本操作创建且未修改的副本；人工改动阻止破坏性回退，审计和已消费费用始终保留。备份恢复或回退后刷新索引。

## 打开应用与首次初始化

### 源码发布与已有安装

本仓库是脱敏源码，不包含已初始化的知识库、账号、API Key、数据库、备份或安装环境。已有实例请继续使用自己的启动器与配置；源码中的本机回环地址和示例目录仅供配置参考。

源码安装后，先在新的项目目录初始化并设置管理密码，再选择自己的知识库并按需配置外部服务。不要在已有数据目录重复初始化。

### 在新目录首次安装

首次初始化、设置管理密码和启动后台需要本机终端，GUI 不自动完成这些操作。使用包含后台运行时的便携 `.app`，将应用路径和新项目目录替换为实际位置：

```sh
FIBER_BIN="/Applications/Fiber bundle.app/Contents/Resources/bin"
"$FIBER_BIN/fiber-setup" check
"$FIBER_BIN/fiber-setup" init --project-root /absolute/new-project
"$FIBER_BIN/fiber-bundle" set-password --project-root /absolute/new-project
"$FIBER_BIN/fiber-backend" start --project-root /absolute/new-project --config config.test.json
```

随后打开桌面应用并登录。初始化不会自动安装或配置 Docker、Hermes、模型、OCR 或 ASR。恢复已有数据请走[恢复流程](#backup)，不要再次初始化覆盖原项目。

源码环境使用 `uv sync --locked` 安装基础依赖；需要 Agent 或加密备份时分别增加 `--extra agent`、`--extra backup`。下文的 `fiber-*` 命令在源码环境可加 `uv run` 前缀；便携应用使用上面的 `FIBER_BIN` 路径。新安装、升级和显式迁移入口见[技术参考](docs/TECHNICAL_REFERENCE.md)。

| -------------- | ------------------------------------------------ |
| 首页           | 查看真实状态、范围、待办和入口；只读刷新         |
| 资料导入       | 普通资料 / fake-expert双入口，指定身份与目标库   |
| 待处理         | 审批、批次、文档、媒体和系统异常的集中入口       |

| 模型与查询     | 配置模型路由、预算，提交和执行问答任务           |
| 资料与版本     | 取回原件、查看来源版本和更新索引                 |
| 消息入口       | 连接飞书 / 微信，查看 Hermes 状态，配置自动入库  |
| 知识关联       | 查看笔记关联图，审核线索，预览和写入 MOC         |
| 文档制作       | 准备文档要求、生成草稿和续改                     |
| 系统设置       | 字体、字号、主题及登录时长                       |
| 执行与费用     | 任务状态、取消、API Key 用量和估算费用           |
| 后台与提醒     | 后台状态、已安装组件、批次提醒和停止管理后台     |

第一次使用建议依次完成：

1. 创建一个日常操作客户端。
2. 接入或新建知识库，给该客户端授予所需权限。
3. 确认索引就绪，导入一份小资料并审核发布。
4. 需要模型回答时，再配置模型、凭据和预算。
5. 按需要连接手机消息入口或外部 Agent，分别进行测试。
6. 做一次完整备份，并在新目录演练恢复。

已有 Markdown 仓库可以先接入并检索，不必先配置模型或机器人。

## 配置客户端与权限

### 创建身份

1. 打开“Agent 与客户端”，切换到“客户端权限”。
2. 填写“客户端名称”，例如“个人资料入口”，点击“创建客户端”。
3. 保存本次显示的新凭证，随后点击“已保存”。凭证只在创建时展示。
4. 选择该客户端，在每个知识库下勾选权限并点击“保存权限”。

| 权限             | 允许的操作                     | 何时需要                               |
| ---------------- | ------------------------------ | -------------------------------------- |
| 查询             | 检索和读取允许范围内的知识证据 | 查询、索引及知识关联分析               |
| 取原件           | 取回保存的来源文件             | 原件下载、部分来源处理操作             |
| 新增             | 入库和受控写入                 | 导入、发布、MOC 写回等；只读库不能授予 |
| 允许申请新建空库 | 提交新库申请                   | 申请仍需在“待审批”中由管理员批准       |

实际操作还会检查库状态、目录范围、来源和任务要求；拥有某项权限不等于所有任务都可执行。不同人或用途建议使用不同身份，避免共用凭证。

“默认参与查询”只控制默认查询选库，不会授予客户端权限。外部 Agent 接入会创建自己的专属查询身份，不需要把管理员密码交给 Agent。

“撤销客户端”会撤销其访问，原凭证不能继续使用。Agent 专属身份的暂停、轮换和撤销，优先在“Agent 接入”中管理。

## 接入和管理知识仓库

### 接入现有库、复制或新建

打开“知识库”→“接入笔记仓库”：

| 方式         | 操作结果                                 | 路径要求                                 |
| ------------ | ---------------------------------------- | ---------------------------------------- |
| 接入现有仓库 | 保留文件原位置，默认只读                 | 选择已有仓库目录                         |
| 复制导入     | 将允许范围内的文件及相对附件复制到新目录 | 填源目录和新目录；新目录最后一级须不存在 |
| 新建仓库     | 在新目录建立空库                         | 父目录须存在，最后一级须不存在           |

1. 选择方式，填写名称和路径。Electron 可用“选择现有目录”“选择父目录”；Web 需填写本机绝对路径。
2. 接入现有库时，决定是否保留“现有仓库只读接入”。需要新增资料或写 MOC，应使用允许写入的仓库。
3. 如只接入部分内容，填写“包含范围”和“排除范围”，每行一个相对路径。空包含表示整个允许范围；已有目录政策和受保护范围仍会先行生效。
4. 选择“索引与查询身份”，按需允许取回原件、入库与写入。
5. 点击“预检接入范围”，核对根路径、笔记数、附件数、字节数和引用问题。
6. 点击“确认接入并建立索引”，查看“接入任务”的阶段、结果和错误。

复制会保留允许范围内的普通文件与相对路径，适合保留 Obsidian 图文结构。缺失、歧义或库外附件会列出问题，不会擅自读取库外文件。当前接入有数量与大小上限；超限时按提示缩小范围。复制失败或取消后可能保留部分目标目录，核对后再处理。

iCloud 仓库须先在本机完整下载并解决冲突；应用不会自动下载占位文件。运行状态目录 `.local-state` 应保持本地存储，不能通过 iCloud 同步运行中的 SQLite 数据库。

### 保存规则与归档（VL2–VL5 候选，尚未上线）

选择已有 Vault 后，应用自动列出可访问的第一层子目录，可按需展开、分页和刷新；这里只发现目录，不读取正文或建立索引。完成接入后，打开该库“管理”→“保存规则”，选择待整理目录、已整理默认目录和共享图片目录，也可为已有 MOC 指定领域目录。每个 Vault 的规则独立，图片目录须在当前写入权限内。

点击“预览保存规则”核对目录及待创建项，再点击“确认保存预览中的规则”。未勾选“确认启用本规则用于随后新准备的发布”时只保存草稿；勾选后仍须重新预览、确认保存，才启用标题笔记布局。旧草稿不会随升级自动启用；缺省继续使用独立目录包。规则只影响之后新准备的发布，不转换旧笔记。

- 普通单篇图文、文档、媒体及通道整理结果保存为 `<待整理目录>/<标题>.md`，图片保存在所选共享目录。重名追加稳定后缀，禁止覆盖。发布前另显示这次实际文件路径，可取消。
- 多分片、带非图片附件的结果与完整 fake-expert Draft 保留完整内容包，整包放入待整理目录；专家资源及 canonical 内容保留在包内，Draft 不因发布变为已核实知识。
- “管理”→“整理与布局迁移”：选择同时具有查询和新增权限的客户端、笔记及明确 MOC。“仅关联 MOC”先预览再确认，不移动文件；“关联并预览归档”或“预览归档”显示目标及待改写链接，确认后才移动。多个 MOC 指向不同目录时必须选定一个目标；图片不随正文归档，移除关联不自动回迁。
- 统一目录规则下，完整 fake-expert Draft 选择“预览专家 Draft 整包归档”或“关联并预览专家 Draft 整包归档”，核对文件数、Book目标及链接后“确认执行此预览”。目标固定取保存规则的“完整专家 Draft 目录”，不跟随普通MOC领域目录；包内文件保持原字节与结构，不拆图、不重编译，不改变Draft/deferred/knowledge_verified=false。普通自动归档仍不搬专家包；未登记的外部包须先走现有接入流程。已在目标目录时只需关联MOC。
- 归档只让本次移动影响的链接问题阻止确认；其他静止笔记中无关的历史缺图/失效引用不阻塞本次操作，也不会被修复。被移动内容的依赖、歧义入链、未知引用语法和专家包内部需要改写的链接仍须核对。
- 开启 MOC 后归档只会在明确关联后准备预览，不会跳过归档确认。关联成功而移动失败时保留关联和文件，使用待处理记录的“核对并恢复此操作”，不要重新发布来覆盖。
- 在 Obsidian 外部移动文件或用编辑器替换文件后，位置检查可能要求重新绑定。使用“外部移动或替换后重新绑定位置”选择对应发布内容，填写新的库内入口路径，预览后确认。此操作更新身份记录并保留人工正文、来源和 MOC；外部移动引起的链接仍需自行核对，不合并尚存的两个副本。
- “可选：历史布局转换”只列出有发布账本的旧包。逐项读取、选择、预览，确认后先备份元数据和实际旧文件，再转换所选项。旧包和图片原件全部保留；Fiber bundle 索引隐藏旧副本，**Obsidian 仍能看到保留的旧目录**。无账本目录及未选中的笔记不处理，删除旧包需另行决定。

目录或权限变化、人工并发修改、未知文件及歧义链接会阻止提交并保留现场。待核对时按记录恢复；备份恢复后的保存规则需重新选择目录并确认启用。已解除或废弃的库仅保留元数据和 MOC 历史，正文不恢复，旧物理绑定失效并留待核对。新布局的跨 Vault 迁移暂不支持，旧布局原有迁库功能保持。

### 默认查询范围与索引

在知识库卡片勾选“默认参与查询”。内置默认问答使用“当前身份有查询权限”与“默认参与查询”的交集；Agent 连接使用其明确勾选的库，消息入口使用单个默认库。

仓库在 Obsidian 或其他编辑器中变更后，进入“资料与版本”→“导入资料”，选择对应的来源身份和目标知识库，点击“更新当前库索引”。更新索引不会调用模型，也不会再次发布文档。遇到“索引过期”应先更新，再查询或分析。

当前导入面板仅列出具有**新增和原件两项权限**的身份 / 库。只读查询身份或只读仓库无法从该面板更新时，可请维护者通过管理索引接口更新，或在源码环境用具有查询权限的客户端凭证执行以下命令，无需为此开放笔记写入权限：

```sh
uv run python -m fiber_bundle.note_search_cli build \
  --project-root /absolute/project --config config.test.json \
  --token-file /absolute/private/client-token.txt --vault-id VAULT_ID
```

该命令更新检索索引，不修改笔记正文。接口合同见[技术参考](docs/TECHNICAL_REFERENCE.md)。

### 解除接入与删除文件

知识库卡片的“管理”中：

- **解除接入**：确认后撤销登记访问，保留原文件，相关入口或任务不能继续依赖旧授权。
- **移到废纸篓**：会移动实际目录；先核对完整路径和同步影响。成功后该库从知识库列表移除，历史操作记录保留；操作未完成或待核对的条目继续显示。受保护库或只接入部分范围的库可能拒绝此操作。
- **重新接入并重建索引**：用于已解除接入的库。若目录已移到系统废纸篓，先在系统中恢复到原位置，再通过下方「接入笔记仓库」重新预检、授权和索引；旧授权不会自动恢复。

## 配置 API Key 与模型

### 区分三种凭证

| 凭证         | 配置位置                                  | 用途                               |
| ------------ | ----------------------------------------- | ---------------------------------- |
| 管理密码     | 本机终端设置，GUI 登录时使用              | 管理知识库、权限和任务             |
| 客户端凭证   | “客户端权限”创建，或由 Agent 接入受管保存 | 外部程序访问授权知识               |
| 模型 API Key | “模型与查询”→“添加模型”；实例密文与本机钥匙串 | 调用用户选择的模型服务 |

飞书 App ID / App Secret 则在“消息入口”单独配置。以上凭证不能互相代替。

### 添加模型与选择默认项

1. 打开“模型与查询”，点击“添加模型”。内置支持 OpenAI、Anthropic、DeepSeek 和 OpenCode Go；选择一家后只需输入 Key 自定义名称与 API Key。
2. 自定义服务商额外填写 API 基础地址（例如 `https://example.com/v1`），默认使用 OpenAI Chat 兼容协议；其他已支持协议在高级设置中选择。本地服务使用明确的回环地址，Key 可选。
3. 点击“读取可用模型”，选择模型及可用的思考强度。发现仅读取列表，不推理或发送知识内容；列表成功不证明调用权限或余额。列表接口不可用时修正连接或手动填写准确模型 ID，保持未验证状态。
4. 点击“保存模型”。取消会清除未保存的 Key；保存不启动任务。已保存列表可编辑、设为默认、停用或删除；被默认项或固定 Agent 引用时需先替换引用。历史调用和费用保留。
5. 需要验证实际调用时，单独点击“测试调用（消耗 Tokens）”。测试只发送固定短句，不读取知识库；其消费与未知预留进入该 Key 的预算和费用页面。

同一 Key 可在弹窗中复用并保存多个模型，共享预算。新 Key 默认每日 **100,000 Tokens**，高级项可调整；“统一模型预算”可修改上限，0 暂停模型步骤。重命名、轮换 Key、添加模型不会清零历史消费。未核实价格时显示费用未知，使用 Tokens 预算；本应用上限与服务商账户余额不同。

旧路由中明确配置的凭据，在地址/协议与提交的 Key 匹配时沿用原预算身份和消费，不扫描其他密钥文件，也不删除原文件。已有金额预算保持原单位，价格未知的新模型不能绕过它；可继续旧的已核价配置，或使用 Tokens 预算的其他 Key。

“设为默认”影响新任务。受管 Agent 可选择“跟随应用默认”或固定模型，已提交任务保留原配置；Key 轮换后旧任务须核对并重新提交。通用 MCP 宿主继续使用自身模型和预算。云端默认模型不等于授权发送全部本地资料。

### 核验运行环境与修正错误

模型可先保存，无需填写受限镜像摘要。页面独立核验 Pi/创作运行环境；若缺失，启动已安装的 Docker，再点击“准备运行环境”，加载本应用附带且摘要已核实的 ARM64 环境。准备不安装 Docker、不启动 Worker 或模型任务；视频/ASR 等其他组件仍按其用途核验。完整摘要在环境诊断中查看。

错误会指出字段与操作步骤：认证失败检查 Key 所属账户/项目；权限失败检查服务商模型或列表权限；额度不足仅在服务商明确报告时提示账户额度；速率限制则等待或调整服务商速率。应用预算不足在“统一模型预算”调整；协议/思考强度不兼容修改协议或选服务商默认；网络错误核对基础地址、网络和证书。系统钥匙串不可用时解锁登录钥匙串，密文损坏则从完整加密备份恢复或重填 Key。失败草稿保留，全局提示到期消失，测试状态仍可追查。

### 旧版：凭据文件与路由

现有固定路由与凭据文件继续兼容。下方“高级：旧版路由配置”用于维护已有路由；新用户使用上述添加向导。旧版凭据文件的操作如下。

GUI 的“本机凭证文件绝对路径”填写**文件路径**，不填写 Key 本身：

1. 在本机准备仅含一个 Key 的纯文本文件，放在仓库、共享目录和公开配置之外，例如 `~/.config/fiber-bundle/omlx.key`。
2. 限制文件权限，例如对实际文件运行 `chmod 600 /absolute/path/model.key`。
3. 在模型配置对应的 `secret_file` 填该文件的绝对路径。

本地 oMLX 凭证使用纯文本单个 Bearer token，不支持 RTF、JSON 或整段 `curl` 命令。现有 OpenCodeGo 云执行读取器另外兼容仅含一个 Key 的 RTF 文件；沿用已配置引用即可，无需为本文复制密钥。不要将 Key 写进 README、配置示例、命令参数或 Git。

### 在 GUI 保存模型路由

1. 打开“模型与查询”→“高级：旧版路由配置”。
2. 已有配置时直接编辑；尚未配置时，使用“导入已准备的配置文件”。模板为 [query-routing.example.json](configs/query-routing.example.json)。
3. 核对本地查询 / 云端答案整理的地址、模型 ID、凭据路径、调用次数、输入输出上限、超时及费用预算。
4. 点击“保存模型配置”。保存只建立配置版本，不调用模型；后续每项任务仍需明确执行。

模板的两个角色初始均为 `null`；空模板不能直接进行问答。首次使用须先在 JSON 中填写需要的角色，再导入。以下为**本地角色的完整结构示例**，镜像摘要、模型 ID、端口和路径须替换为已准备环境的实际值：

```json
{
  "schema": "query-routing-preparation/v1",
  "enabled": false,
  "local_query": {
    "image": "sha256:<已核实的受限执行镜像的64位摘要>",
    "endpoint": "http://127.0.0.1:8001/v1/chat/completions",
    "model": "<服务实际返回的模型ID>",
    "secret_file": "/absolute/path/omlx.key",
    "max_input_tokens": 4096,
    "max_output_tokens": 512,
    "max_request_bytes": 65536,
    "max_calls": 1,
    "daily_calls": 10,
    "timeout_seconds": 60
  },
  "cloud_answer": null,
  "approved_backups": []
}
```

这里的限额仅是示例。`enabled` 必须保持 `false`，表示不开放自动执行；把它改成 `true` 会被拒绝。本地地址要求字面回环地址和 `/v1/chat/completions` 路径，模型 ID 应精确匹配服务配置。

配置 OpenCodeGo 云整理时，把 [execution.example.json](configs/execution.example.json) 的完整对象填入 `cloud_answer`，补齐真实的价格与预算，将 `max_attempts` 设为 `1`，并核对任务额度不超过每日额度。示例中的 `null` 价格 / 限额及占位凭据路径须先替换；它不是可直接执行的配置。备用保持 `approved_backups: []` 即不声明备用，失败不会自动换模型。

内置“本地引用草稿 + 云端整理”先做本地问答，云端只收到该答案及其中引文。外部通用 MCP 的模型由其宿主配置，数据发送和费用也由宿主控制。受管 Agent 直接使用云模型的发布边界见[外部 Agent](#agents)。

### 发起一次问答

在“模型与查询”选择“查询身份”，分别填写“问题”和“检索词”，点击“入队本地查询”。例如问题是“这份资料中电机维护需要注意什么”，检索词填写笔记中实际出现的“电机 维护”。入队后勾选“批准此任务的一次模型调用”，点击“启动一次”，核对引用和当前来源；需要云整理时再按卡片单独准备、执行。任务未完成或执行失败时，在“执行与费用”查看原因。

## 导入文件、文章和消息

### 本地文件导入

1. 打开“资料与版本”→“导入资料”。
2. 选择“来源身份”和“目标知识库”。当前导入面板要求身份同时具有该库的新增和原件权限。
3. 选择“保存原件”或“导入并处理”，再选择文件。
4. 按来源选择普通提取、原生文本 / Office XML、OCR 或旧 DOC 转换。OCR、转换和完整 fake-expert 需要事先准备相应运行资格；按钮不可用时先检查“资料处理设置”。
5. Markdown 含相对附件时，选择配套文件并填写正文中的原引用路径。缺件不会自动读取或下载。
6. 点击“开始导入”，查看进度和“刷新导入状态”。
7. 已处理候选在“文档审核”核对并发布，随后更新当前库索引。

“保存原件”只归档来源，不等于生成可检索笔记。普通确定性提取的模型额度为零；完整 fake-expert 是独立 Draft 任务，需单独核对执行条件和费用。

### 审核已保存来源

在“文档审核”中选择来源身份、知识库，点击“读取已保存来源”，选定材料后“准备来源处理任务”。需要执行的任务再点击“确认执行这项来源任务”；此路径可能使用已配置模型费用额度。

候选完成后下载原件，核对来源顺序、正文、图像、数字、单位、表格与公式，为各来源单元填写判断和理由，点击“记录人工审核”，再点击“发布已审核文档”。来源覆盖不完整时需补交完整来源并新建任务。记录审核与发布是两个动作。

在“资料与版本”可按身份和库读取来源版本、取回有权限的原件。原件、提取候选和已发布笔记是不同阶段。

### 飞书自动入库与网站白名单

连接独立飞书入口后，在该卡片展开“自动入库与网站白名单”：

1. 选择具有新增权限的可写目标库，勾选“自动归档新消息”。
2. 选择资料类型、允许的网站，以及“同批合并（保留消息顺序）”或“每条消息分别保存”。
3. 设置累计归档、附件 / 网页 / 图片 / 字幕获取上限；需要手机回执时另外开启并设置回执额度。
4. 如需文章正文或已有字幕，分别启用对应提取选项。
5. 点击“保存自动入库策略”，确认入口运行且没有阻塞原因，再发送一条新资料测试。

预设网站包括 X、公众号、B站、YouTube 和微信视频号。自定义域名每行一个主机名，不填完整 URL、路径或通配符；空白名单不表示允许所有网站。没有相应提取器时只保存链接。

此功能默认关闭，仅处理生效后的新消息。历史批次须在“历史待确认批次”中明确选择，点击“处理所选批次 / 明确恢复”。归档、下载和回执额度累计保留，暂停、重新保存或重启不会清零。

文章正文 / 原图、视频元数据 / 已有字幕的提取与归档分开。当前自动视频提取只处理不超过 **60 秒**的范围，不下载整段视频，不做模型调用、OCR 或 ASR。视频号卡片、无字幕、登录受限或内容不完整时会显示“待补全”或“仅链接已保存”。

未启用文章正文提取时只保存链接，不会自动生成文档审核任务。链接正文在本入口的“最近入库记录”中审核；开启提取后，旧链接仍需明确重试，不会自动补跑历史。

出现“正文 / 字幕待审核”后，点击“核对正文 / 图片 / 字幕并审核”，填写实际审核理由，完成核对项后“记录人工审核”，再“确认发布到所选知识库”。“原件已归档”不等于全文可检索。

当前自动入库支持本项目独立飞书知识入口；微信直连自动入库暂不支持。真实网站提取质量与手机端完整流程的验收范围见 [STATUS](docs/STATUS.md)，预设网站列表不代表所有链接都能取得正文。

## 连接飞书、微信与 Hermes

查询处理会保存阶段进度。存储短暂繁忙或进程中断后，仍在处理中的新查询可复用与原请求、模型配置一致的已保存成功结果，继续本地检索与答案校验；不会重复调用已成功的模型请求或重复结算额度。恢复与发送前仍检查当前权限和来源。模型结果未确认、成功缓存缺失或无法核验时停止处理，保留原调用记录和预留额度供核对；已经结束的历史查询不会自动重放。

### 先准备运行环境

“消息入口”使用项目专属 Hermes 实例，配置生成独立私有 home，不接管个人 Hermes 或已有其他机器人。页面需要已校验的 **Hermes 固定运行清单绝对路径**（`runtime-manifest.json`），不会自动安装或更新 Hermes。

已有项目专属 gateway 会作为既有入口展示；个人 gateway 不会自动成为本项目入口。Hermes 负责消息通道，本机运行；文档、媒体等受限执行可能使用 Docker，不能把这些 Docker Worker 当作飞书机器人。固定运行时的准备与维护见[技术参考](docs/TECHNICAL_REFERENCE.md)。

### 连接飞书机器人

1. 在飞书开放平台创建独立自建应用，启用机器人，开通收消息事件与发送消息权限，使用长连接并发布应用。
2. 在“消息入口”点击“新增飞书 / 微信入口”，选择“飞书”。
3. 填名称、App ID、App Secret，或导入本机凭证文件路径；填写已准备的 Hermes 运行清单路径。
4. 选择“本人访问身份”和“默认知识库”，确认身份已启用、知识库已接入。按用途选择“允许取回原件”“允许入库”；保存会设置本库查询权限，并按当前勾选设置原件/入库权限，已有身份授权不能代替表单勾选。只读库不能授予入库权限。
5. 填写本配置版本的有限额度，**0 表示不允许相应操作，不表示无限制**。未启用自动入库策略的普通查询入口，启动前必须将“最多接收查询”和“最多手机回复”均设为正数。“原文证据，零模型调用”可保持“最多模型调用”为0；使用模型回答并接收查询时，模型额度也须为正数。附件下载额度按需独立设置。
6. 普通飞书查询无需启用fake-expert，两项专家额度保持0。若启用“私聊 fake-expert 文件指令”，保存前必须同时勾选“允许取回原件”“允许入库”，并将“本次配置的专家指令上限”设为正数；“专家状态回执上限”按需独立设置，可为0。
7. 点击“保存配置与所选权限”→“验证连接”。保存成功不代表入口已经启动；凭证验证通过后仍须确认飞书平台事件权限已发布。
8. 点击“开始本人配对”，用自己的飞书账号私聊该机器人，发送页面给出的配对短语；回到 GUI 确认捕获的本人身份。
9. 核对已保存的权限与额度，再点击“启动 / 重新连接”，用手机发送 `查询本库：检索词或问题`。自动入库另有独立策略和额度，按[飞书自动入库与网站白名单](#飞书自动入库与网站白名单)配置。

保存和启动前会检查缺少的权限与额度，并在表单或入口卡片列出具体项目。后台仍会再次检查最新状态。请按发生的步骤核对：

| 发生步骤 | 优先检查与处理 |
| --- | --- |
| 保存配置 | 启用fake-expert时，原件权限、入库权限及正数专家指令额度须同时满足；关闭时两项专家额度须为0。 |
| 已确认本人后启动 | 普通查询入口的查询/手机回复额度须为正数；模型回答还需模型额度。修改后先保存，再手动启动；仅调整额度无需重新配对。 |

以上条件都满足时，保留具体操作步骤和连接诊断信息继续排查；这句通用提示本身不能证明名称、权限或Secret有误。修正设置后须保存，再重新执行本次操作。

此入口按绑定本人私聊处理，使用单个默认库，不跨库回退。先选“原文证据，零模型调用”可验证检索；选择本地或本地加云回答前，先完成模型路由配置。卡片中的“测试原文查询”可在本机核对，不发送手机消息；明确执行模型查询会消耗相应额度。

微信中的资料可经支持的“其他应用”分享方式转给飞书机器人，再按上节归档、审核和发布。实际能分享的类型取决于手机应用；不要把任意聊天转发都视为已取得完整来源。

### 连接微信

新增入口时选择“微信”，保存独立配置后点击“扫码登录 / 重新登录”。二维码来自实际上游登录接口；本人扫码后在 GUI 确认身份，再显式启动。凭证过期时先暂停，重新登录并确认。当前真实微信绑定验收仍暂缓，不能把界面就绪当作手机端已验证。

### 查看状态、暂停和移除

点击“刷新连接状态”，分别核对本人绑定、Hermes 进程、平台连接、权限 / 额度和最近错误。心跳过期或连接中断会使状态失效；顶部管理服务可达不能代替这些状态。

- **暂停入口**：停止本应用管理的入口执行，保留资料和审计。
- **解除绑定**：撤销本人绑定，重新使用时需配对或登录确认。
- **移除连接**：按确认页处理连接及本应用拥有的配置；保留笔记、原件和执行审计。不会删除飞书开放平台应用或接管个人 Hermes。

操作后核对停止与清理结果。若显示待人工核对或发送结果未知，先核对手机实际收件，再按记录处理，不要连续重试发送。

<a id="agents"></a>

## 外部 Agent 挂载知识库并回答

这里的“挂载”是给 Agent 提供带权限的检索工具。知识仍保存在本机，通过当前授权返回证据；它不会写入大模型权重。

### 方式一：GUI 管理的本机 Hermes

1. 打开“Agent 与客户端”→“Agent 接入”→“新建连接”。
2. 选择“本机 Hermes”，填写连接名称，勾选允许查询的知识库。
3. 选择“仅依据知识库”或“知识库优先，可补充一般知识”，选择已配置的受管模型，核对检索与模型限额。
4. 点击“保存暂停连接”，再“应用接入配置”。应用会为该连接准备独立配置。
5. 点击“授权并启用查询”，等待无模型工具检查通过；也可单独点击“验证连接（无模型）”。
6. 在问答区分别填写“测试问题”和“检索词”，必要时用“从问题建议检索词（本机，无模型）”生成候选并人工核对。
7. 点击“执行 Hermes 问答测试”，核对引用、来源、模型补充和执行轨迹。

受管路径先通过 MCP 检索并复核当前来源，再让 Hermes 使用选定模型生成引用草稿。“仅依据知识库”限制回答依据；允许一般知识补充时，补充内容独立展示。测试答案不会自动保存为知识，引用通过也不代表语义已由人工核验。

**当前正式包的受管模型选择支持本机 `local-primary`。** 源码已有 `opencodego-primary` 云端 Agent 直接回答扩展，尚未进入正式包，不能只靠填写云 Key 在当前正式 GUI 启用。升级后该模式会发送问题及检索片段到 OpenCodeGo，与内置“只整理本地答案”的云整理路径不同。准确发布状态见 [STATUS](docs/STATUS.md)。

受管请求也可使用导出信息中的实际 transport 文件路径：

```sh
fiber-agent request \
  --connection-file /absolute/state/agent-connections/CONNECTION_ID/transport.json \
  --question '电机维护的注意事项是什么？' \
  --query '电机 维护'
```

这个入口适用于按上述步骤配置的受管 Hermes，仍检查当前连接、范围和预算，不会自动改接个人飞书 gateway。

### 方式二：通用 MCP 宿主

1. 新建连接时选择“通用 MCP 客户端”，勾选查询库，保存、应用配置并授权查询。
2. 点击“导出 MCP 配置”，在**同一台机器**的外部 MCP 宿主中导入生成的 `mcpServers` 项。使用原始命令、参数和文件引用，不要自行把 token 嵌入配置。
3. 按外部宿主的要求重新加载 MCP，确认可以调用 `fiber_list_vaults`、`fiber_search`、`fiber_index_status` 三个只读工具。
4. 在宿主配置模型及回答规则，再用一个库内确实存在的术语提问，检查实际工具调用和引用。

可给外部 Agent 配置如下规则：

> 回答知识问题前，先核对 Fiber bundle 可访问库与索引状态，再用问题中的术语调用 fiber_search。依据返回的笔记路径及来源定位引用回答；无命中或检索失败时说明资料不足。只有允许补充时才使用模型一般知识，并与知识库依据分开标明。索引过期先要求更新，不冒用历史结果。

通用 MCP 只提供工具；是否先检索、选什么模型、向云端发送什么内容和发生多少费用，由外部宿主控制。“工具可用”或“已导出”不证明外部宿主已加载，更不证明每次回答强制检索。需要受管的先检索后回答保证时，使用方式一。

当前首版是本机 loopback / stdio 接入，导出中的凭据文件引用不能直接用于另一台机器或云端 Agent。不要把服务直接暴露公网作为远程接入办法。

### 连接维护

“暂停查询”会拒绝后续检索；“轮换凭证”使旧凭证失效，新凭证需重新应用和授权；“永久撤销连接”用于停用。可在“操作记录”查看摘要，运行中的自有操作可取消。权限、配置、程序或来源改变后，旧测试可能显示过期，需要重新验证。

## 查看笔记关联与建立 MOC

MOC（Map of Content）是把相关笔记组织到一起的目录笔记。已知分类时可直接在知识库的整理页面选笔记和已登记 MOC，无需先运行知识关联模型。手工关联与归档预览会同时列出已有受管MOC文件的链接改写；确认后保留人工正文并同步目录链接。一篇笔记可以属于多个 MOC，MOC 与文件夹结构相互独立。

### 查看关联图

1. 打开“知识关联”，选择有查询权限的“分析身份”和“知识库”。
2. 在“笔记列表与分析环境”查看持续显示的诊断。索引过期时点击“更新此知识库索引”；位置异常时点击“打开知识库核对位置”，完成核对再更新索引。
3. 首次分析点击“检查本地分析环境”，校验成功后点击“配置并启用此分析环境”。仅检查本机已有固定镜像和模型，不下载、不读取笔记、不调用云模型；没有可用环境时按下方技术参考准备。已有“启用分析”只切换已保存配置。
4. 展开“选择笔记并创建有限任务”，勾选笔记，点击“创建所选笔记的分析任务”，再在任务卡点击“执行此任务”。单任务最多 100 篇。
5. 完成后查看“建议列表”或“笔记关联图”，按需切换 MOC 分组、关联线索或标题提及。
6. 在图上搜索定位、查看邻居、拖动固定节点、适应画布或重置视图；点击节点查看笔记路径、原文片段和分组。

笔记列表支持按标题/路径查找、每页100篇，已登记身份的内容优先展示。选择仅作用于本页，切页不会隐式选择整库；未登记的普通笔记仍需下方显式track流程。次要建议或任务视图失败时，已成功读取的笔记仍可显示，权限失效则清除。

若旧发布文件已不存在，进入“知识库 → 管理 → 整理与布局迁移 → 外部移动或替换后重新绑定位置”。找得到实际文件时预览并重绑；确认正文全部缺失时可“预览标记文件缺失 → 确认标记缺失（保留历史）”。这只隔离缺失发布以恢复其余内容的索引，不删除来源/去重、不恢复正文；部分包仍存在时拒绝此标记，必须实际核对。找回文件后可对已标记记录再次重绑。

图例区分显式链接、待审核线索和已接受线索。拖动只改变布局，不改笔记；节点距离和模型相似分数不能当作事实关系。大库可能显示有界局部视图，请同时看覆盖数量。无 WebGL 时使用节点列表。

Electron 可通过详情打开原笔记；Web 显示位置，由用户在本机编辑器打开。外部编辑或撤权后旧证据可能失效，应更新索引或重建分析。

若笔记显示“尚未登记稳定身份”，不能直接选中分析。普通文件存在不等于已登记；可使用已有 `fiber-notes track` 流程，登记身份需要新增权限。下面的 CLI 参数均需替换为实际值，`SHA256` 为当前文件字节摘要，路径相对于 Vault：

```sh
fiber-notes track --project-root /absolute/project --config config.test.json \
  --token-file /absolute/private/client-token.txt --vault-id VAULT_ID \
  --note-path '主题/笔记.md' --expected-sha256 SHA256
```

固定图谱环境和配置入口见 [技术参考](docs/TECHNICAL_REFERENCE.md) 与 [knowledge-graph-runtime.example.json](configs/knowledge-graph-runtime.example.json)。该可选分析环境与问答用的 oMLX / OpenCodeGo 配置不同。

### 从建议建立 MOC

1. 在“建议类型”选择“MOC 分组”，核对建议中的笔记及原文。
2. 填写“审核理由”，点击“接受线索”。这一步只记录审核，不写文件。
3. 点击“准备 MOC 写回”。需要该身份具有目标库新增权限，且库可写。
4. 新建时保留生成的 MOC 标识，修订号为 `0`，填写库内 Markdown 路径，例如 `MOCs/电机维护.md`，文件摘要填 `absent`。目标父目录应已存在。
5. 点击“生成写回预览”，核对完整 Markdown 内容和路径。
6. 点击“确认写入 MOC”，完成后检查写回记录及实际文件，按需更新索引。

更新已有受管 MOC 时，使用其已有标识、当前修订号和当前文件 SHA256，不能继续使用 `0` / `absent`。版本或摘要不一致会拒绝写入，应先核对外部编辑并重新预览。

系统写回保留人工正文和人工归属；“准备撤销本建议贡献”只撤销该建议的贡献，不等于删除整份 MOC。未知 / 中断写回先“对账已有写回”，不直接重复执行。

### 维护人工 MOC

也可以用 Obsidian 或其他 Markdown 编辑器创建目录笔记，加入 `[[相关笔记]]` 链接，再更新索引。已有人工 MOC 不需要为了接入而重新生成；普通 Markdown 文件不会自动成为受管 MOC 记录。 GUI 可在“知识库 → 管理 → 整理与布局迁移 → 已有 MOC 登记接入”读取保存规则中的 MOC 目录，选择已有文件并“预览接入已有 MOC → 确认登记并保留人工内容”。只追加系统关联区，原人工字节和已有稳定身份保留；接入后刷新可在“明确关联的 MOC”选择。失败通过“核对并恢复 MOC 登记”核对，不重复新建。若需接入受控归属 / 写回，使用 `fiber-moc create/show/link/plan-file/apply-file` 对应流程，参数见 `fiber-moc --help` 和[技术参考](docs/TECHNICAL_REFERENCE.md)。

## 备份、恢复与分发

### 在 GUI 准备完整备份

1. 打开“备份与恢复”，点击“准备完整数据备份”。
2. 核对显示的操作记录和终端命令。“已准备”还没有生成备份。
3. 停止管理后台、消息接收器、全部 Worker 和仍在写入仓库的编辑 / 同步操作；等待 Agent 操作完成或取消并确认停止。关闭窗口不等于停机，备份命令不会代停进程。
4. 在本机交互终端执行页面给出的 `fiber-backup execute --request ...` 命令。使用实际项目根和配置文件；便携应用命令位于 `FIBER_BIN`。
5. 隐藏输入备份长密码（建议至少 16 个 ASCII 字符）并另行妥善保存；丢失密码无法解密。
6. 完成后恢复同一部署后台，点击“刷新备份状态”。按记录给出的 `verify` 命令核对密文；需要验证可恢复性时，在新目录演练恢复。

也可直接在终端指定一个全新备份位置；目的父目录须已存在：

```sh
fiber-backup create --project-root /absolute/source-project --config config.test.json \
  --destination /absolute/private-output/new-backup
fiber-backup verify --bundle /absolute/private-output/new-backup
```

密码只在交互终端输入，不填进 GUI 或命令参数。完整备份生成 `state.fbenc`、`vaults.fbenc` 和最后写入的完成标记 `bundle.json`。`verify` 只核对密文与标记摘要，不能代替密码认证及实际恢复验证。

完整备份覆盖状态、历史、原件和符合范围的已登记知识库；状态可能含客户端 token、账号和游标等敏感信息。新模型向导保存的托管 Key 以备份密码加密封装，恢复时绑定新的本机钥匙串账户；备份和恢复均需要可用、已解锁的系统钥匙串。旧外部凭据文件、浏览器登录和 Agent / 通道专属秘密仍须重配。额外的项目内配置需按 `--include-config` 明确选择，不能假定所有外部引用都在备份中。

元数据快照、Git checkpoint、单独复制 `.app` 或只复制 Markdown，都不是完整数据备份。不要同步运行中的 `.local-state` 作为备份。

### 恢复到新目录

GUI 可在已有备份记录上点击“准备干净恢复”，再按显示命令离线执行。也可以直接运行：

```sh
fiber-backup restore --bundle /absolute/private-output/new-backup \
  --destination /absolute/new-restored-project
```

恢复目的目录必须全新。完成后副本默认锁定，旧管理员会话和客户端访问失效，通道及待执行工作停用，历史费用保留，未知副作用不重放。先核对数据、凭据、模型和运行环境，再进行单主机切换：

托管模型恢复保留模型 ID、默认项、Agent 固定引用与预算历史，重新绑定秘密路径和本机钥匙串，清除旧调用验证标记；不会自动恢复测试或其他历史任务。恢复失败会保留锁定副本与真实原因，不回退明文。普通配置导出和应用分发包不含 Key。

```sh
fiber-backup retire --project-root /absolute/source-project --config config.test.json
fiber-backup activate --project-root /absolute/new-restored-project --confirm-source-stopped
```

只有确认源项目停止、不再同时处理同一业务后才能激活新副本。激活本身不启动服务或启用客户端；还需在新项目设置管理密码、启动后台，逐项重新授权，更新索引，重新配对消息入口。Agent 连接需轮换凭证、应用配置、授权并重验。

### 分发知识或迁移整套应用

| 目的                      | 交付内容                                                      | 接收端操作                                               |
| ------------------------- | ------------------------------------------------------------- | -------------------------------------------------------- |
| 分享笔记库                | 明确选择的 Markdown 与相对附件，例如经核对的 Vault 目录 / ZIP | 解压后在“知识库”接入现有目录，重新设置本地权限并建立索引 |
| 迁移自己的完整项目        | 完整加密备份包 + 单独保管的密码 + 兼容应用版本                | 新目录恢复，核对源机停用，再激活和重配                   |
| 给外部 Agent 使用本机知识 | 专属只读 MCP 接入配置                                         | 同机宿主导入、授权并验证，不分发完整状态库               |
| 安装应用                  | 对应发行版本的 `.app` / DMG                                   | 应用安装与项目数据初始化 / 恢复分开完成                  |

当前 GUI 提供复制导入和备份准备，没有一键制作脱敏知识分享包的向导。分享目录 / ZIP 时自行选择内容并保留相对附件；不要把 `.local-state`、客户端 token、模型 Key、登录 Profile 或私密原件混入普通分享包。复制后的文件不继承本项目访问控制，接收端须重新授权。

当前 macOS 分发为 Apple Silicon 本机包，ad-hoc 签名，未公证；实际最新包与跨机验收状态以 [STATUS](docs/STATUS.md) 为准。旧 DMG 不一定包含当前 GUI 更新，不要仅凭相同版本号判断功能一致。

## 外观、费用与后台管理

顶部操作提示在成功后显示5秒、错误时显示10秒，然后自动消失；字段旁的缺项说明及连接异常状态会保留供核对。

“系统设置”支持中英文字体和字号分别选择、主题、密度、行高与减少动效，修改即时预览，保存仅影响当前浏览器或 Electron 客户端。安装新字体后可点击“刷新本机字体”；缺字或字体被卸载时使用内置字体补足。

自动退出默认一小时，可在页面调整；保存影响下次登录，不延长当前会话。到期前有提醒。重新登录可恢复当前标签页有限的已编辑文本草稿，文件、密码、Key、token 和选择项不恢复，恢复文本不会自动提交。刷新或关窗会丢失临时草稿。

“执行与费用”按日期和 API Key 配置筛选用量图与每日明细。日期为 UTC、含起止日，最长 366 天。费用是按调用时配置单价的估算，未知预留单列，实际账单以服务商为准；调用数含失败 / 未知预留，不等同于成功次数。本地调用不计云费用。

“后台与提醒”查看后台和组件版本、批次提醒；“明确停止管理后台”用于本应用管理的后台实例，消息入口须另行暂停并确认停止。取消任务不退还已发生费用；外部结果未知时先对账。

## 常见问题

| 现象                                   | 优先检查                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------- |
| GUI 打不开 / 显示离线                  | 当前部署后台是否启动，是否使用 `127.0.0.1:8765`；不要重复初始化                              |
| 管理接口可达，但手机不回复             | “消息入口”的本人绑定、Hermes 进程、平台连接、查询 / 回复额度，平台权限是否已发布             |
| 只能看库，不能入库或写 MOC             | 仓库是否只读、客户端是否有新增权限、目标范围是否允许写入                                     |
| 问答没有资料                           | 身份 / 库范围、检索词、发布状态和索引；只归档原件不会生成全文笔记                            |
| 报索引过期                             | 在“资料与版本”选择对应身份 / 库，点击“更新当前库索引”                                        |
| 模型配置保存失败                       | JSON 是否补齐角色、`enabled:false`、有效摘要 / 模型 ID / 路径 / 限额；是否与其他窗口版本冲突 |
| 模型报认证错误                         | 凭据文件格式、路径和服务要求；本地 oMLX 不接受 RTF，路径不能填成 Key 文本                    |
| 通用 MCP 验证通过，外部 Agent 仍不检索 | 宿主是否实际导入并加载、工具是否可调用、回答规则是否要求检索；GUI 检查不控制宿主行为         |
| 关联分析无可选笔记                     | 索引、稳定身份登记、已配置图谱环境和分析开关                                                 |
| MOC 写回冲突                           | 当前文件 SHA256、受管 MOC 修订号和路径；重新核对并生成预览                                   |
| 备份显示已准备但没有文件               | 是否已停全部写入进程，并在交互终端执行离线命令                                               |
| 恢复后不能直接使用旧连接               | 默认停用是恢复流程的一部分；核对源机停止、激活、重新配置并授权                               |

需要查看完整 API、CLI 及模块职责时，使用 [技术参考](docs/TECHNICAL_REFERENCE.md)；未完成的真实微信、网站质量、需登录媒体或跨机验收，以 [项目状态](docs/STATUS.md) 为准。

### 统一提取与模型预算（源码候选）

知识库 → 管理 → 保存规则 → 提取与入库策略：基础提取无需 API Key 或提取次数额度；Pi + Skill 使用模型与查询中已有的云模型配置，并须明确允许发送资料。执行与费用 → 统一模型预算，按凭据设置每日/月度 tokens 或金额上限；本地账本不代表服务商账户余额。

“完整性校验”和“直接保存到 Inbox”独立设置。关闭校验仍可直接保存，产物标记未校验；关闭直接保存则进入待确认。权限、格式、路径及来源摘要始终检查。设置只影响新任务，不补跑历史；预算不足后从任务已完成阶段显式继续。配置变更导致旧冻结任务失效时需核对，不能重复未知费用请求。

### 视频提取（源码候选）

待处理 → 媒体审核 → 视频提取：选择有查询、原件与新增权限的身份和目标库，上传 MP4/WAV 或填写公开 Bilibili/YouTube 链接，输入完整时长。字幕优先；无字幕时必须配置已验证本地 ASR 并确认术语表，可明确使用空表。画面选项保留每10秒抽样帧，不代表已理解全部画面。Pi 整理使用目标库策略中的模型、外发许可和统一预算。

视频运行设置需预装固定 ffmpeg 媒体镜像；公开链接另需固定 yt-dlp 镜像。本地 ASR 仅接受包内资格清单的镜像、权重与资源，不自动下载模型。无此能力可提供 SRT/VTT。平台登录/反爬限制应改用合法取得的本地文件，不能靠更换模型 Key 解决。当前新管线保护范围为最长2小时、文件沿用资料处理容量（最多16MiB），每段60秒；旧媒体任务保留旧保护范围。

刷新查看分段、缺项和实际错误；取消保留原件、已完成分段及费用，明确继续时复用已完成段。未知模型费用需核对，失败调用不会盲目重试。关完整性校验可直接保存有正文的未校验产物；空转写、源摘要变化、撤权和不安全路径始终阻止发布。默认保留转写/关键帧/覆盖记录，原始媒体在归档中保留。

### Pi + fake-expert 章节材料（源码候选）

资料导入 → fake-expert 专用导入，使用固定完整 compiler，并在目标库处理策略选择 Pi + Skill、处理身份与云内容许可。无需填写专家指令次数额度。编译器先生成页码/文本摘要绑定的章节单元，Pi 逐单元或分片提出语义 proposal，再由编译器验证完整 workpack 后构建 Draft；章节调用与费用在执行与费用按同一 Key 预算记录。

资料与版本/导入记录显示章节、分片、缺项、调用数与继续操作。预算不足保留已完成材料，补充统一预算后明确继续；未知费用请求不盲目重试。未取得可绑定的章节标题时请提供同源、已核对结构的 workpack，或选择普通文档提取。扫描/视觉 profile 须明确后端，并提供同源已接受结构审核与运行条件；不自动替换 OCR、制造 Review 或下载权重。

新处理策略的有效 Draft 按独立开关保存到 Inbox，旧策略沿用 Book。关完整性校验不绕过 compiler 输入有效性验证；独立语义审核仍 deferred、knowledge_verified=false。真实扫描 profile 与真实模型语义质量尚待专项验收，原生合成 PDF 的离线编译通过不能代替这些验收。

### Fiber 接入 Skill 与质量范围（源码候选）

Agent 与客户端 → 连接配置：选择库与“全部可见资料 / 仅完整性通过”。保存新配置会暂停连接，应用并明确授权后再读取；旧连接保存前保持原范围。完整性通过不等于事实核验，旧笔记缺质量记录显示未知。

连接详情 → 接入 Skill、安装与试查知识，可下载不含凭据与正文的接入 Skill、查看安装步骤，并进行不调用模型的只读试查。将解压目录放到外部宿主支持的 Skill 目录，在同机宿主导入导出的 MCP 配置并启用。Fiber 侧检查、配置导出和宿主实际加载分开显示；外部宿主费用由宿主管理，Fiber 默认未知。不要把私有凭据文件引用直接用于跨设备连接。


### 导出离线主题 Skill

在「知识库 → 管理 → 对外使用」选择一个已启用、具有本库查询权限的连接。选择单本书/所选资料、已有MOC及直接引用或整个当前授权库，预览成员、版本、体积和缺项后确认生成。原件与附件默认不包含；显式选择后仍须独立原件权限。生成和下载前会复核来源与权限；来源变化须重新预览，不会覆盖旧快照。导出无模型调用，无需 API Key 或提取额度。

可在向导的版本记录中查看、取消或明确继续失败任务。完整ZIP校验通过后才可下载；离线包可在无Fiber服务时读取SKILL.md/INDEX.md及相对引用。专家子包原字节保持Draft/deferred/knowledge_verified=false，Python只读查询组件的要求见包内INSTALL.md。下载不表示宿主已加载；撤权不能收回已导出的副本。含绝对私有路径或疑似凭据的资料需先制作可分享版本。

已发布的专家产物详情可用「导出此专家模块的主题 Skill」直达向导；长视频的待确认、预算不足或失败状态会显示在首页/待处理中心的所选身份与库范围中，跳转后继续核对。

### 本地 UI 检查（开发者）

安装开发依赖后运行 `npm run lint:ui -- --url http://127.0.0.1:8766/`。默认只检查未登录页面，不读取或导出登录材料。已登录桌面检查需先正常退出管理应用，保留后台，再显式提供 `--electron <应用可执行文件> --profile <该实例独立profile> --require-auth`；结束后正常重开桌面。不要把8765和8766的profile混用。

检查使用固定提交的 [lintapple](https://github.com/gholtzap/lintapple/tree/90ddc736af6f2712903d53dd9a463445e109f586) 和 `ui-policy.json`，覆盖1180/390/1440px视口、字体、对比度、控件及ARIA。390px是同一Electron页面内的视口模拟，非原生窗口最小宽度验收。关闭弹窗、隐藏辅助标题、SVG文字与密集导航有明确范围的例外，同时由 `tests/e2e/lintapple_guards.mjs` 独立核对真实目标、键盘、焦点、44px导航触区及4.5:1对比度。报告默认写入系统临时目录，可通过 `--output` 指定；包含本机页面信息，请勿作为分发内容。静态检查采用减少动效，不替代人工动效和真实平台业务验收。

Atlas 知识库列表的“更新索引”可打开详情页索引面板，选择有查询权限的身份后手动更新，并查看状态、笔记数和完成时间。更新不调用模型、不执行整理；笔记位置异常时先到“整理与迁移 → 批量核对外部改动”核对原登记。

消息查询保留原精确检索；零命中时以当前身份可见的笔记标题为词汇拆分中文复合词，并保留主题做有限条件回退。单次最多12次本地检索，不增加模型规划调用、不扩大知识库或权限范围；最终仍未命中时提示调整关键词或核对知识库及索引，不把零命中表述为权限拒绝。
