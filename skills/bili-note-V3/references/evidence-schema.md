## Evidence Segment

`evidence/segments.jsonl` is the source for note composition. Each row contains a time range, normalized transcript text, cue indices, local frame paths, and cloud analyses. Visual-only segments are preserved even when no one is speaking.

`evidence/illustration_bindings.jsonl` is required when a crop is embedded in a full-evidence
note. Each binding records the `illustration_id`, manifest `frame_id`/`timestamp`, evidence
`segment_id`, exact crop caption, a non-empty `note_anchor`, and `verified=true`. The binding
audit prevents a correct crop from being attached to the wrong claim or time range.

`evidence/illustration_placement.json` is generated by `build_evidence_timeline.py`. Each frame
is bound to exactly one evidence segment: its nearest transcript segment when it falls inside the
attach window, otherwise its own visual-only segment. For every created crop it records the
`primary_segment_id`, the `representative_text` (the closest transcript sentence), `offset_seconds`,
and `ocr_keywords`. This is the single source for where a crop belongs. A binding must use the
`primary_segment_id` from this map, and the note must embed each created crop exactly once, near
the `note_anchor` text in the prose. The visual-evidence audit enforces all three rules
(`illustration_placement_consistency` and `note_illustration_placement`).

`frames/frame_manifest.json` schema 1.1 records the scan profile, focus scope, candidate and deduplication counts, maximum temporal gap, scan runs, and the source of each selected frame (`interval`, `scene`, `iframe`, or pinned `cue`). A focused rerun with `--append` keeps existing frame IDs and adds a new run record.

When local ASR is used, `transcript/asr_coverage.json` records the audio duration, merged covered ranges, uncovered time ranges, per-chunk status, and the audio hash used by the cache. A failed or empty chunk is not silently treated as complete evidence.

## Reproducibility Rules

- Preserve platform, stable source id, source URL, extraction time, title, part/chapter information, and media duration. Bilibili jobs also retain `bvid` for compatibility.
- Preserve both the platform-declared duration and the measured local-media duration. A
  `source_coverage.json` report with `complete=true` is required before downstream evidence
  stages for jobs that have source metadata or source media.
- Preserve raw transcript and correction records.
- Keep selected frame timestamps stable.
- Treat `frames/frame_manifest.json` as the single timestamp source. Audit every visual row and
  illustration against it with `scripts/audit_visual_evidence.py` before writing the note.
- Do not include danmaku, comments, live chat, or authentication secrets in any evidence source.
- Do not delete failed visual rows to improve coverage.
- Regenerate downstream evidence after transcript, glossary, frame, or visual-result changes.
- Keep full selected frames in the evidence package, but use only crops from `illustrations/`
  as finished-note images for schema 2.1 jobs.
- Delete only files marked `managed: true` in `media_manifest.json`, and only after both the
  internal final audit and published-note audit pass.
- Published notes and copied illustrations must remain usable after source media and ASR audio
  cleanup.
- Do not hand-write `visual_results.jsonl`, alter `asr_coverage.json`, or append synthetic
  transcript cues to make a gate pass. Repair the upstream evidence or disclose the gap.

## Access and handoff variation

`metadata/access.json` keeps the legacy `status` field for compatibility and adds orthogonal
process dimensions:

- `access_state`: `unknown`, `public_verified`, `auth_required`, `authenticated`,
  `member_authorized`, `denied`, or `drm_blocked`;
- `source_state`: `not_acquired`, `complete`, `preview_limited`, `partial`, `unverified`, or
  `failed`; and
- `handoff_state`: `not_required`, `pending`, `ready`, `unavailable`, or `failed`.

`browser_backend` records only `edge`, `chrome`, or `generic_browser`; no browser profile,
Cookie, Local Storage, password, authorization header, or signed URL is material evidence.

Before reuse, `scripts/job_gate.py` must report `decision=reusable`. A prior note or a
legacy pipeline state is not sufficient. If source coverage is incomplete, use
`scripts/access_preflight.py --backend edge|chrome|generic_browser`; its `waiting_user_action`
result is a resumable access phase and must not be published as a completed note.

## Audio-Only Variation

Jobs initialized with `--evidence-mode audio-only` keep the same privacy, terminology,
transcript, evidence, publication, and cleanup records, but deliberately skip visual evidence.

- `metadata/job.json` records `policies.evidence_mode = "audio_only"`, disables cloud vision,
  and sets `note_illustrations` to `none`.
- `source/` contains `audio.*` rather than `video.*`; it is registered as `source_audio`.
- `frames/`, `visual/`, and `illustrations/` remain empty. Their pipeline phases are `skipped`.
- `evidence/coverage.json` records `transcript_coverage_ratio` and marks visual coverage as
  `not_applicable` rather than manufacturing a visual score.
- The final note must contain `音频优先整理，未核验画面内容` and must not embed an image.
- The publisher may emit an empty asset list. It still verifies the note hash and can safely
  delete registered `source_audio` and `derived_audio` files after both audits pass.
