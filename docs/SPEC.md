# Fiber bundle 需求规格

初次确认日期：2026-09-26。更新日期：2026-09-27，用户明确同意增加 Electron macOS GUI 交付和 WeChatBridge 参考范围。状态：用户讨论确认后的施工基线；不是已实现能力声明。

## 1. 文档权威与最终目标

本文件、PLAN.md、DECISIONS.md、STATUS.md 是当前施工上下文。原 `00_README.md`、`01_BUILD_PLAN.md`、`02_SOURCE_AUDIT.md`、`03_SOURCE_EXCERPTS.md` 及 evidence 保留为历史规划和上传源码证据，不代表本机部署。与本次明确决策不同的旧设计，以本组文档为准；未明确解决的新矛盾必须询问用户，不自行推断。SPEC 后续不得擅自修改。

构建独立的本地知识系统：用户在手机微信向 Hermes 提交资料，专用 Pi Agent 调用 Skill/MCP 提取整理，通过受控发布写入 Obsidian；用户在微信查询知识，或要求制作总结、报告文件。系统提供接口供其他 Agent 保存、检索、问答和取回原件。第一版验证后，第二阶段接入 Carme，Carme 是调用方，不是知识系统业务正本。

第一版交付包含可安装的 macOS 桌面 GUI，采用 Web 前端 + Electron 封装 + 独立本地后台。桌面应用承载资料、任务、审批、Vault、模型和备份管理，不以浏览器快捷方式代替应用交付；不要求另外维护一套原生管理界面。

第一版只有用户本人使用，个人与供应商 Vault 主要防止混放，允许授权后的跨库查询；外部 Agent 仍按独立凭证限制读写范围。

## 2. 测试位置与部署约束

所有路径相对项目根目录 `[project-root]`：

| 用途 | 配置位置 |
|---|---|
| 个人知识测试库 | `./test vault/temp_vault1/` |
| 供应商知识测试库 | `./test vault/temp_vault2/` |

用户第二个路径按同级测试库解释，非系统根目录 `/temp_vault2`。两库仅用于测试，不代表已建立或已接入。不得自动接入真实个人库、供应商库或扫描旧系统数据。

部署在本机常开的 Mac；全部组件在该机运行。Vault 长期目标支持 iCloud Drive，当前上述测试库不宣称受 iCloud 同步。数据库、队列、凭证置于主机本地，不同步运行中数据库。其他设备可编辑、移动、重命名和删除 Vault 笔记；查询以主机当前可见版本为准，检测未下载或冲突时提示，不承诺全设备最新。

分发面向用户自己的其他 Mac，以迁移/备用为目标，同时只运行一台主机。完整备份恢复用于切换，不能仅复制 Vault 代替系统迁移。安装包不含个人数据、凭证和浏览器登录状态。

桌面窗口与知识后台生命周期分离：关闭管理窗口不停止微信收件或已启动的后台任务；重新打开窗口连接同一后台，不重复启动接收进程或任务。明确停止后台属于独立操作，并按任务取消/恢复规则处理。桌面端须显示后台运行、停止或连接失败状态，不能把打开窗口等同于后台就绪。Electron 界面沙盒不能代替 Pi 受限执行环境。

## 3. 入口、会话与收件

- 微信仅绑定本人身份；转发记录中的昵称、作者、角色均为来源数据，不授予权限。
- 新入口切到 Hermes，OpenClaw 暂不使用，旧任务不迁移、旧数据不删除；实际停用和切换属于后续里程碑，不是本文创建动作。
- 现有 Hermes 飞书保持原用途，不扩大工具权限，不共享临时附件和任务上下文。2026-10-07 用户授权另建独立 Hermes gateway，连接新的飞书知识 Bot，接收手机微信经“其他应用”转发的 ZIP 和公众号链接。新入口使用独立 App ID/Secret、Hermes home、会话和附件缓存、Fiber 客户端/本人绑定；仅获明确授权测试库权限，不复制旧飞书配置、凭证或任务。后台批次与原件账本可复用，但来源范围和身份必须区分。
- 手机微信 → Hermes 保留为直接入口；手机微信 → 飞书知识 Bot → 独立 Hermes gateway 增加为分享入口。[WeChatBridge](https://github.com/freestylefly/WeChatBridge) 仅作为 M0 的参考项目，考察 macOS 微信主动导出聊天归档、文本/媒体关联、批次与原件保留的做法；桌面 Share Extension 接收的导出包不等于手机经 iLink 交付的卡片 payload。第一版不新增系统 Share Extension，不据该项目宣称 Hermes 能完整展开合并转发。2026-10-08 用户确认新增 Web/Electron 本地资料导入入口，复用后台来源/资产、身份/Vault 授权、任务、人工审核及发布；不替代手机入口，不递归监视目录。GUI 和独立飞书知识入口可显式选择普通提取或完整 fake-expert PDF，冻结策略、大小/页数/输出与预算；完整 Skill 接线、分片发布与检索须分别验收，不以既有页面检查子集冒称完整 Skill。
- 专用知识入口：纯资料转发默认保存；带问题只回答，明确“也保存”才入库。“保存刚才那份”默认保存原资料，不自动保存该轮分析。
- 未归档资料与生成草稿保留在当前会话，可追问，不进入长期知识检索。说“新话题”显式切换，旧会话保留，可定位恢复。
- 清理会话须展示范围并确认，妥善停止未结束任务后清理临时文件；正式入库知识不受影响。
- 单条消息暂存窗口可配置，初值静默 3 秒，新消息重置计时。窗口内多条消息必须确认后才能交给模型处理或正式归档；时间仅是分批启发式，不能证明消息来源。
- 批次操作：保存为一份、分别保存、仅用于咨询、取消。咨询无问题时询问目的；同批资料后带问题且尚未入库，按咨询处理。
- 确认提示发出后成员固定，新资料另建批次；显式要求才合并。范围不明时提供简短候选，不猜任务或资料。
- 待确认批次保留至处理/取消/会话清理；每 24 小时进入合并提醒，每天最多一条摘要。可逐项关闭提醒，关闭不删除待办。仅批次确认周期提醒，术语、预算、登录等其他待办只通知一次。
- 连续归档使用合并完成回执；其他需处理事项合并为带短编号的清单。
- 先持久保存接收事件和实际字节，再执行模型；接收、暂存、已保存原件、已发布笔记、已交付必须区分。凭证与正文不写普通日志。

## 4. 必需输入与提取

第一版最终验收必须覆盖：公众号链接/卡片、X 普通帖子/长文、聊天文本/逐条转发、合并转发、图片/截图、PDF（含扫描件）、Office（Word/Excel/PPT）、音视频文件/链接。按阶段启用，不将暂未接入类型删除出范围。音视频平台范围按已验证能力列矩阵，不宣称任意网站均支持。

- 公众号/X 长文复用用户指定 `wechat-to-obsidian`；音视频复用 `bili-note-V3`。用户报告已长期验证，当前系统接入、隔离兼容及新发布入口仍需验证。
- 已确认扩展（2026-10-15）：无可用字幕先自动ASR；完整音轨所有分片均无有效文字且无处理错误时，可按画面关键帧文字/图表生成笔记，明确语音未核验；不伪造字幕，不因模型缺失、超时或部分失败切换。审核方式和既有保存目录规则保持，费用/原件/去重与明确恢复保留。
- Skill 路径：`[icloud-skills]/wechat-to-obsidian`；同根目录 `bili-note-V3`。原 Skill 不在本轮改动。
- 网页仅处理用户提交页面和正文所需资源；外部引用只保留链接，不递归抓取。
- 保存实际可取得的全文、图片、表格及原始附件；平台未交付内容不得补造。合并转发只能获取部分时保留部分、提示补交，不能宣称已完整归档。
- 原文忠实保留，仅调整排版；摘要、新增信息、关联、疑点独立分区。单篇笔记含属性（标题、作者、原始链接、标签、日期、MOC 等）、整理区和全文图片；原始附件单独保存。
- 原文、来源主张、用户修订、模型分析分层，疑点或冲突另列，不自动改成系统认定的结论。
- 图片、扫描 PDF、Office 自动提取；不确定数字/单位/表格保留定位并待核对，相关笔记不正式发布。未发现疑点不代表人工验证。
- 提取失败或不完整保留已收原件，在受限待处理区重试/补充，未补齐不发布正式笔记。完整但未分类笔记仍可检索，二者不得混淆。
- 直接发送的音视频原件长期保留；链接下载媒体仅在处理和发布检查通过后清理，用户指定保留除外。保留转录、时间戳、关键图片和来源。失败不提前清理。
- 视频复用预先认可的领域术语表，无新增歧义自动处理；遇不确定术语微信集中询问。覆盖与画面/语音证据状态如实记录。
- 登录内容通过预配置专用浏览器；验证/登录失效暂停，通知用户本机处理。不导出浏览器秘密，不绕过访问控制。

## 5. 知识组织与生命周期

- 自动选择一个主 Vault；不确定时询问。明确目标且有权限时指定优先，分类不一致只提示。不重复跨库保存全文，归档默认仅关联同库，不自动跨库链接。
- 新资料独立成笔记，检索相关知识并指出新增与矛盾，不自动改写旧正文。MOC 可增量更新和创建；无合适归属可暂待分类。检索不能依赖 MOC 是否收录。
- 单篇笔记可同时属于多个主题 MOC，形成笔记与主题的多对多知识网络；人工指定的 MOC 归属保留，系统可增加其他归属；人工正文不可自动覆盖。
- 知识图谱与既有笔记检索使用已有标题、Markdown正文和属性，不对笔记内嵌图片执行OCR；图片及引用完整保留供人工查阅，图片中的独有信息不视为已提取的检索证据。
- 旧库只读建索引，不批量改属性、路径或格式；来源不明旧笔记在索引标为“历史笔记，来源未核实”。
- 人工修改更新索引，查询区分用户修订与原文。外部移动/重命名保持稳定身份；冲突保留双方，不静默覆盖。旧文件可用旁路 ID 映射，不强写属性。
- 重复来源内容不变复用已有笔记；内容变化保存新来源版本和差异，不覆盖人工内容。事件重试幂等，用户再次明确请求不能被正文哈希吞掉。
- 明确纠正 Vault 归属可迁移笔记，保留 ID；附件只复制，原库全部保留。原库人工 MOC 归属及审计保留，目标仅加入明确指定的 MOC，未指定则待分类。正文笔记链接保留并列出跨库后待修复项。
- 删除笔记撤出正常检索，保留原件和来源恢复入口，不自动重建。其他有效引用保持可用。
- 取消任务停止后续处理，保留原件和检查点，不发布未完成笔记。取消批次可撤销本批新增笔记/MOC 链接，保留操作账本；已有/共用内容不动，人工修改笔记保留并列为例外。已发消息、已传出数据和费用不能收回。
- 入库触发局部增量整理；全库整理由用户主动发起，无定期全库整理。

## 6. 查询和执行模型

- 默认检索当前会话资料及获授权、配置为默认参与的 Vault 正式笔记。各 Vault 的访问授权与默认搜索开关独立。待处理内容需明确指定；未分 MOC 的完整笔记可查。
- 来源标注极简，如 `[1]` 加短标题/可用链接。证据不足或过旧说明，不强行回答；冲突列差异及来源，不自行裁决。
- 查询默认不联网补充，用户明确要求才搜；用户提交链接后的采集不受此规则禁止。
- 可以检索 Agent 分析产物，但不视为独立证据；关键事实追溯原始来源，不能核对则明确是已有分析。
- Hermes 与 Pi 分别配置 API 地址、模型和凭证；云模型备用列表仅使用用户预先批准项，遵守预算并记录切换。
- 两库默认可使用已配置云模型。指定 Pi + oMLX 查询时，云端 Hermes 可理解问题/调度，原始检索内容仅交本地执行方；本地生成答案允许回到云端 Hermes 整理，包含其中摘录/报价。此模式不是全程离线隐私模式。
- 指定本地执行失败保留问题并报告，不自动切换云端。
- 所有资料处理与文档制作统一由专用 Pi 调用 Skill/MCP，专用配置不继承个人 Pi 全部权限。确定性收件、授权、预算、状态与发布检查由后台承担。
- Pi 在受限环境运行，只获任务工作目录和受控接口；不直接读写 Vault、控制数据库或宿主凭证目录。默认允许联网，查询不联网是任务规则而非网络强制隔离；这不授予任意数据外传权限。
- Skill/MCP 固定已验证版本，显式更新检查后仅新任务采用；运行任务保持旧版。使用安装环境可控制的能力边界，不靠提示词代替文件授权。

## 7. 文档任务与可靠运行

- 第一版支持基于资料制作总结/汇报，执行器可配置，默认 Pi + 自配置 API；不接管代码修改等通用任务。格式随执行器能力，不承诺固定清单或伪造格式。
- 生成文件以未核验草稿回传微信，程序检查存在、非空及可上传；不默认增加内容复核 Agent，不将基本文件检查等同事实验证。
- 草稿保留会话、可续改，只有明确要求才存为分析产物。
- 一项任务一个活跃执行负责人；多入口/页面查看不重复运行。新消息按意图关联修改、独立归档或问答，歧义候选确认。
- 补充要求可安全追加时追加，否则完成当前版本后自动修订；保留版本与进度。任务固定输入版本，发现相关更新提醒，由用户选择是否纳入。
- 问答和修改优先，重任务限并发排队并在安全阶段让出资源。
- 临时抓取/模型错误有限退避重试，受预算限制；权限、登录、缺内容暂停。重启自动恢复可重入步骤，发布先对账，未知副作用不盲重放。
- 微信文件发送失败保留本机文件、记录失败，不自动重试、不重新生成、不自动换平台；文字可用则告知，整个通道不可用则下次查询展示。
- 单任务及每日费用上限覆盖模型、OCR、ASR、视觉和 Agent；价格未知不得按零计费，须配置计价/可控额度后放行。微信可批准绑定任务、金额、有效期的一次追加，长期限额在管理页调整。具体额度未设置，不得默认为无限。

## 8. 外部接口、权限与管理

- 本机接口提供：异步保存、状态查询、问答、证据检索、固定版本原件取回、产物提交；受限环境有专用连接通道，不开放局域网/外网。
- 保存先返回 job ID/持久化状态，只有发布成功返回正式笔记引用。
- 每 Agent 独立凭证，按 Vault 配置查询、取原件、新增、创建 Vault 权限，单独可撤销。外部 Agent 可直接新增，经归档检查发布，不默认人工审批，不允许覆盖旧笔记。
- GUI 外部 Agent 接入专项按 [HANDOFF](HANDOFF.md#agent-integration-gui-20261008) 推进：首版 Hermes 与通用 MCP 的新连接仅授予明确库范围的 query；保存默认暂停，应用、验证连接和真实问答分别显式执行。原件/新增等既有权限不因本专项自动授予，通用 MCP 只暴露三个只读工具。
- 受管 Hermes 入口在模型生成前完成当前轮检索与来源复核；鉴权、索引、来源或版本失败时阻止生成/交付，不伪装成无命中。支持仅据证据和明确区分模型补充两种策略；输出为未独立语义核验的草稿。GUI 需展示实际能力和验证版本，静态安装检测、工具发现或普通 MCP 配置不等同先检索后回答已验证；现有内置证据回答合同保持。
- 2026-10-09 用户授权将该 Agent 的真实验证由本地 Qwen3.8 改为已配置 OpenCodeGo。受管连接可显式选择本机或云端主配置，云端发送问题与所选库的检索片段并展示处理位置、次数及费用；不默认选云、不自动切换备用。此选择独立于原 M10 本地查询/云整理模式，其原件隔离合同保持。
- 生成分析标记为产物，附来源 ID/版本；目标库扩大来源可见范围时必须本机授权。来源声明无法独自证明外部 Agent 已完整披露，应记录信任边界。
- 可授权在指定根目录创建空 Vault，用户在本机确认权限前不能写入资料；不得由模型扩大范围。
- 撤权即时阻止后续接口读取；本系统受控任务停止并阻止交付。已被外部调用方取得的数据无法保证收回或阻止其自主发送。
- 第二阶段 Carme 各账号分别凭证/范围，可信后端绑定身份，不由模型传参冒认。
